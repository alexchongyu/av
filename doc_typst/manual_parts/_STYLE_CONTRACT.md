# av User's Manual — 챕터 집필 계약서 (반드시 준수)

이 문서는 `doc_typst/av_users_manual.typ`(마스터)에 `#include` 될 챕터 파일들의
작성 규칙이다. 마스터가 모든 스타일·폰트·페이지·헬퍼를 소유한다.

## 0. 출력 파일

- 파일명: `doc_typst/manual_parts/ch<NN>_<slug>.typ` (지정된 이름 그대로)
- 인코딩 UTF-8, 한국어 설명체(~합니다/~입니다).
- 기술 용어·식별자(PSNR, SSIM, `--comp`, `Ctrl+B`, `av.ini` 등)는 원문 유지.

## 1. 절대 금지 (마스터가 소유)

- `#import`, `#set`, `#show`, `#let`, `#pagebreak`, `#set page`, `#set text` **금지**
- 문서 타이틀/목차/헤더/푸터 작성 금지
- 다른 챕터 파일 수정 금지, 마스터 파일 수정 금지
- `typst compile` 실행 금지 (마스터가 아직 없으므로 반드시 실패한다)

## 2. 구조

파일은 반드시 레벨 1 제목으로 시작한다. 마스터가 레벨 1 앞에 자동으로
페이지를 분리하므로 `#pagebreak()`를 쓰지 않는다.

```typst
= 세 영상 블록 비교 — `--comp`

짧은 도입 문단 (이 장에서 무엇을 배우는지 2~4줄).

== 기본 사용법

=== 블록 크기 지정
```

- 레벨은 `=`(장) / `==`(절) / `===`(소절)까지만 사용. 번호는 마스터가 붙인다.
- 각 절은 "무엇을 / 왜 / 어떻게(예시) / 주의" 흐름을 지킨다.

## 3. 마스터가 제공하는 헬퍼 (이것만 사용 가능)

| 헬퍼 | 사용법 | 용도 |
|---|---|---|
| `#key(...)` | `#key("Ctrl+B")` | 키캡 박스. 키는 **항상** 이걸로 표기 |
| `#note[...]` | `#note[내용]` | 참고 박스 (파란색) |
| `#tip[...]` | `#tip[내용]` | 실전 팁 박스 (초록색) |
| `#warn[...]` | `#warn[내용]` | 주의/함정 박스 (주황색) |
| `#ex("제목")[...]` | `#ex("PSNR 게이트 예")[본문]` | 번호 붙은 "예시" 블록 |

그림 함수(인자 없음, `#figure`+캡션 포함되어 있음) — **배정된 것만** 호출:

`#fig_ui_layout()` `#fig_panel_modes()` `#fig_zoom_pan_model()`
`#fig_pixel_priority()` `#fig_diff_pipeline()` `#fig_diff_colormaps()`
`#fig_comp_layout()` `#fig_comp_ranking()` `#fig_comp_nav()`
`#fig_analysis_windows()` `#fig_sequence_sync()` `#fig_ci_flow()`
`#fig_color_pipeline()`

호출은 문단과 문단 사이에 단독 줄로: `#fig_comp_layout()`

## 4. 표

`#table`을 직접 쓰되 스타일 인자(stroke/fill/inset)는 쓰지 않는다 —
마스터의 `#set table(...)`이 적용된다. 첫 행은 헤더 셀로 `*굵게*` 표기.

```typst
#table(
  columns: (auto, 1fr),
  [*옵션*], [*설명*],
  [`--blk <WxH>`], [블록 크기. 기본 `8x8`],
)
```

- 페이지 폭을 넘기지 않도록 마지막 열은 `1fr`을 쓴다.
- 열이 3개를 넘고 설명이 길면 표를 나눈다.

## 5. 코드/명령 예시

명령·CSV·출력은 반드시 코드 블록(```)이나 인라인 raw(백틱)로 넣는다.

````typst
```
av --comp orig.png fw.png hw.png --blk 16x16 --num_blk 24
```
````

- 프롬프트 기호(`$`)는 붙이지 않는다 (복붙 가능하게).
- 출력 예시는 `#` 주석으로 설명을 덧붙인다.
- **예시는 실제로 동작하는 문법이어야 한다.** 소스에서 확인한 옵션·기본값만 쓴다.

## 6. Typst 특수문자 (가장 흔한 컴파일/렌더 사고)

| 상황 | 처리 |
|---|---|
| CLI 플래그 `--comp` | **반드시 raw**: `` `--comp` `` — 본문에 맨몸으로 쓰면 `–`(en dash)로 변환됨 |
| `<WxH>` 같은 꺾쇠 | raw 안에 넣는다. 본문의 `<...>`는 typst 라벨 문법이라 깨진다 |
| `~` | 본문에서는 `\~` (raw 안은 그대로) |
| `#` | 본문에서는 `\#` |
| `@` | 본문에서는 `\@` |
| `_` `*` | 리터럴이면 `\_` `\*` |
| 하이픈 `-` 단독 | 범위 표기는 `\~` 또는 `#sym.tilde` 대신 `0.1\~100` 형태 사용 |
| 화살표·대시 | `\u{2192}`(→) `\u{2014}`(—) `\u{2264}`(≤) 처럼 유니코드 이스케이프 권장 |
| 표 셀 안 `|` | `\|` |

작성 후 스스로 위 목록을 훑어 점검한다 (특히 `--`, `~`, `<>`).

## 7. 내용 품질 기준 (가장 중요)

1. **소스가 유일한 진실**이다. 추측 금지. 각 기능은 반드시 소스에서 확인한다:
   - CLI 파싱: `src/app.cpp` `parse_cli()`, 도움말: `src/main.cpp` / `av --help`
   - 키 처리: `src/app.cpp` 스캔코드 `switch`
   - 핫키 표(권위 있는 목록): `src/ui/main_window.cpp` `render_hotkey_help_window()`
   - 헤드리스: `src/metrics_cli.cpp`
   - 렌더/오버레이: `src/ui/image_panel.cpp`, `src/ui/main_window.cpp`
   - 상태/기본값: `src/app.h`
   - 기존 요약: `doc_typst/av_cheat_sheet.typ`
2. **하나도 빠뜨리지 않는다.** 배정된 항목 목록을 체크리스트로 삼고, 마지막에
   전 항목이 문서에 실제로 등장하는지 자기 검증(grep)한다.
3. **모든 기능에 구체적 예시**를 붙인다. CLI는 실행 가능한 명령 줄, GUI는
   "어떤 상황에서 → 어떤 키를 → 무엇이 보인다" 형태의 조작 시나리오.
4. 기본값·범위·단위·영속화 여부를 명시한다 (예: 기본 `8x8`, 범위 `2\~1024`).
5. DDI(디스플레이 드라이버 IC) 보상 IP 검증이라는 사용 맥락을 살려 실무
   활용 팁을 곁들인다.
6. 분량: 챕터당 A4 3\~7쪽 상당. 표·예시를 아끼지 말 것.

## 9. 반환 값

에이전트의 최종 텍스트는 사람이 읽는 보고가 아니라 **데이터**다. 파일을 쓴 뒤
다음 형식의 짧은 요약만 반환한다:

```

LINES: <줄 수>
SECTIONS: <== 절 제목들 콤마 구분>

NOTES: <소스에서 발견한, 치트시트와 다른 사실이나 주의점>
```
